# 软件工程组织(Software Engineering Organizations)

[软件工程实践](https://en.wikipedia.org/wiki/Software_engineering)及其[历史](https://en.wikipedia.org/wiki/History_of_software_engineering),本身就是一部关于[人性](https://en.wikipedia.org/wiki/No_Silver_Bullet)、[协调](https://en.wikipedia.org/wiki/Software_development_process)与沟通的复杂研究。

## 软件工程(Software Engineering)

* [Studying Attitudes and Social Norms in Agile Software Development (2019)](https://arxiv.org/pdf/1904.09225.pdf)(研究敏捷软件开发中的态度与社会规范),Lucas Gren
    > 这篇论文综述了关于态度与社会规范的研究,并将其与敏捷软件开发的语境相连接。作者提出了若干社会心理学的补充理论,这些理论对于进一步理解敏捷团队中人因相关的研究显然大有裨益。

* [Happiness and the productivity of software engineers (2019)](https://arxiv.org/ftp/arxiv/papers/1904/1904.08239.pdf)(幸福感与软件工程师的生产力),Daniel Graziotin & Fabian Fagerholm
    > 这篇论文概述了关于软件开发者幸福感的研究。你将了解到:为什么让软件开发者快乐很重要、他们实际上有多快乐、什么让他们不快乐,以及在开发软件期间对他们的生产力应有什么样的预期。

* [Why Software Projects need Heroes (Lessons Learned from 1100+ Projects) (2019)](https://arxiv.org/pdf/1904.09954.pdf)(为什么软件项目需要"英雄"(来自 1100+ 项目的经验教训)),Suvodeep Majumder、Joymallya Chakraborty、Amritanshu Agrawal & Tim Menzies
    > 这篇论文从代码质量的角度探讨了项目中"英雄"的影响。作者识别出 1100 多个 GitHub 开源项目中的"英雄开发者"。基于分析,他们发现大多数项目都是*"英雄"项目*,而且*英雄开发者*(贡献代码最多的人)提交的代码所产生的 bug 远少于其他开发者——这与现有文献的结论相反。

## 组织模拟(Organizational Simulation)

* [:scroll:](common-ground-and-coordination-in-joint-activity.pdf) [Common Ground and Coordination in Joint Activity](http://www.researchgate.net/profile/David-Woods-19/publication/227992178_Common_Ground_and_Coordination_in_Joint_Activity/links/5ba284c892851ca9ed15cdc0/Common-Ground-and-Coordination-in-Joint-Activity.pdf)(联合活动中的共同基础与协调),Klein、Feltovich 与 Woods

  > 这篇论文的诞生,源于一群背景横跨数学、心理学与人工智能的研究者(Feltovich 与 Bradshaw),与现代决策制定及认知系统工程研究的开创者(Klein 与 Woods)聚在一起,追问"团队究竟如何运转"。文中勾勒的概念,为设计"需要多个行动者(无论是人还是软件代理!)协同才能成功"的工具与环境提供了框架和方向。这篇开创性论文不仅深入剖析了人与团队协作,还剖析了协调、协作、合作这些有时不可见的活动究竟由什么构成,以及各方在此过程中彼此之间的契约与预期。这篇论文对多个领域产生了深远影响:军事情报、航天运输与航空,以及近年的软件工程与 Web 运维。让我带你梳理一下:这篇论文从何而来、为什么它对软件的未来至关重要,以及——我敢肯定——它对未来的预示。- @allspaw
